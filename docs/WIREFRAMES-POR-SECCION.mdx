# Wireframes por Sección — Composición de Componentes y Estructuras

> **Objetivo:** mostrar **cómo se compone cada sección** — qué componentes la forman, en qué orden se apilan y cómo es su estructura interna — mediante **wireframes ASCII**, para servir de guía en el rediseño.

---

## 0. Leyenda de Wireframes

| Símbolo | Significado |
|---|---|
| `[──]` | Tarjeta / panel (card) |
| `┌─┐` | Contenedor con borde |
| `▸` | Menú desplegable / acordeón |
| `▶` | Tab / pestaña |
| `◈` | KPI / stat card |
| `●` | Badge / indicador de estado |
| `◎` | Botón principal (CTA) |
| `◐` | Botón secundario |
| `✎` | Acción editar |
| `🗑` | Acción eliminar |
| `🔍` | Búsqueda / filtro |
| `...` | Continuación (paginación / scroll) |

```
│ └────────────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────────┘
```

**Estructura del componente `DataTable.vue`:**
```
DataTable
├── Toolbar (title + slot toolbar)
├── Desktop: <table> (md:block)
│   ├── thead: <th sortable @click="toggleSort">  → emite sort-change si serverPagination
│   ├── tbody: <tr> con slots `cell-{key}` / type currency|number|date|datetime|custom
│   └── slot `actions` (opacity-0 → hover)
├── Mobile: cards (md:hidden) — mismos slots
├── Empty State (icono + emptyMessage)
└── Pagination (visiblePageNumbers + showingFrom/To + prev/next)
```

**Props:** `columns[]`, `data[]`, `loading`, `totalRows`, `serverPagination`, `title`, `emptyMessage` — **Emits:** `sort-change {key,dir}`, `row-click`, `page-change`.

## 20. Conclusión

Este documento de **wireframes por sección** revela:

1. **Hay 5 patrones de layout que se repiten** (Shell, KPIs+Tabla, Detalle, Tabs, CRUD modal) — el rediseño debe formalizarlos como componentes (AppShell, DataTable 2.0, DetailLayout, Tabs, CRUDManager).
2. **Los modales son el punto más fragmentado**: 4 mecanismos distintos para la misma función → unificar en `Modal.vue` + `ConfirmDialog` + `ToastProvider`.
3. **Cada sección tiene ya su wireframe aquí** — sirve como blueprint para implementar Aurora 2.0 sin inventar estructuras nuevas, solo unificando las existentes.

> **Referencias:** `docs/FRONTEND-POR-RUTAS.mdx` (mapa de rutas/modales/detalles), `docs/ANALISIS-REDISENO-COMPLETO.mdx` (plan por fases), `docs/ANALISIS-ERP-COMPLETO.mdx`.
