## 5. Bugs confirmados y corregidos (12)

Cada bug fue reproducido vía suite o sonda, diagnosticado con causa raíz y corregido. Verificados por re-ejecución.

### 5.1 Carrito / Checkout (S14–S15) — `products.stock` no existe
- **Síntoma:** `POST /api/v1/cart/items` → 500 `code: 42703` (undefined column). Checkout → `EMPTY_CART` (cascada).
- **Causa raíz:** `sale-service` consultaba `.select('id, price, stock')` sobre la tabla `products`, que **no tiene columna `stock`** (el inventario vive en `inventory`, agregado por almacén).
- **Fix (3 sitios):**
  - `AddCartItemUseCase._resolveServerProduct` → stock agregado desde `inventory` (suma de `stock` por `product_id`, excluyendo soft-deleted).
  - `CheckoutUseCase._validateStock` → agrega stock por producto desde `inventory` con `IN (...)`.
  - `subscribers/checkLowStock` → obtiene stock real desde `inventory` en vez de `products.stock`.
- **Archivos:** `backend/services/sale-service/src/usecases/index.js`, `subscribers/index.js`.
- **Verificación:** S14 ✅, S15 ✅, S13 ✅ (decremento intacto), S53 ✅ (reversión intacta).

### 5.2 Platform Admin `get_all_companies` (S38) — `p.company_id` inexistente
- **Síntoma:** `GET /api/v1/platform-admin/companies?limit=10` → 400 `column p.company_id does not exist`.
- **Causa raíz:** el RPC contaba `SELECT COUNT(*) FROM products p WHERE p.company_id = c.id`, pero `products` no tiene `company_id`.
- **Fix:** **Migración 060** — redefine el RPC contando productos vía `created_by → users.company_id`.
- **Verificación:** S38 ✅.

### 5.3 `is_platform_admin()` falso con service key (S38 stats)
- **Síntoma:** `GET /api/v1/platform-admin/stats` → 500/403.
- **Causa raíz:** con service key, `auth.uid()` es NULL → `is_platform_admin()` siempre falso.
- **Fix:** **Migración 058** — acepta `request.jwt.claims.role IN ('service_role','platform_admin')` además del rol admin vía auth.uid().
- **Verificación:** S38 stats ✅ con datos reales (`mrr, total_users: 9, total_clients: 7...`).

### 5.4 Multi-tenant: `req.companyId` nunca se establecía
- **Síntoma:** las consultas tenant-scoped no filtraban por empresa (datos cruzados potenciales).
- **Causa raíz:** `tenantContext` en `@erp/shared-kernel` no asignaba `req.companyId` antes de `tenantStorage.run`.
- **Fix:** `packages/shared-kernel/src/index.js` → `req.companyId = companyId` (desde JWT o header) + `tenantStorage.run({supabase, companyId})`.
- **Impacto:** afectaba a todos los servicios que usan `tenantStorage`.

### 5.5 Crear cliente sin UUID (S11)
- **Síntoma:** `POST /clients` → 500 (PK null en tabla con `id uuid default gen_random_uuid()` — el insert explícito con `id: undefined` rompía el default).
- **Causa raíz:** `ClientMapper.toPersistence` no incluía `id` y el usecase no generaba UUID.
- **Fix:** `CreateClientUseCase` → `id: input.id || randomUUID()`; `ClientMapper.toPersistence` → `id` primero.
- **Archivos:** `backend/services/user-service/src/usecases/index.js`, `mappers/index.js`.

### 5.6 CRM: slug de pipeline sin default (S34)
- **Síntoma:** 23502 `slug` NOT NULL sin valor.
- **Causa raíz:** la tabla `crm_pipelines.slug` no tiene default; el repo insertaba sin slug.
- **Fix:** `SupabasePipelineRepository.create` genera slug desde el nombre (lowercase, NFD, `[^a-z0-9]+ → _`).

### 5.7 CRM: slug duplicado de etapas (S34)
- **Síntoma:** 23505 violación UNIQUE `(company_id, slug)` en `lead_stages`.
- **Fix:** retry loop (0..9) que usa `${baseSlug}_${attempt+1}`; insert dual `lead_stages` + `pipeline_stages`.

### 5.8 CRM: trigger de automatizaciones 42883 (S35)
- **Síntoma:** 42883 — `fn_trigger_automations(uuid,...)` no existe para PKs INTEGER.
- **Causa raíz:** migración 056 cambió la firma a UUID; `leads`/`dynamic_form_submissions` tienen PK INTEGER.
- **Fix:** **Migración 059** — overload con `(uuid, varchar, varchar, integer, jsonb)` que delega con `NULL::uuid`.

### 5.9 CRM: columnas inexistentes en conversión (S37)
- **Síntoma:** `convertToClient` actualizaba `status`/`converted_client_id` que no existen.
- **Fix:** actualiza `converted_at` + `client_id` (reales); inserta cliente con `{id: randomUUID(), company_id, ...}`.

### 5.10 CRM: `company_id` ausente en POSTs del controller
- **Fix:** `controller.js` de user-service envía `user_id: req.user.id` en leads y `company_id: req.companyId` en stages/activities/notes.

### 5.11 Integraciones: schema drift (S50–S52)
- **Síntoma:** webhooks/automations/logs apuntaban a columnas que no existen (migración 046).
- **Fix:** `integration.controller.js` mapea el schema real (`events TEXT[]`, `http_method`, `filter_conditions`, `retry_*`, etc.); `router.js` usa service key y `requireAuth` setea `req.user`.

### 5.12 Form Builder: submit con RPC inexistente (S46)
- **Síntoma:** 500 al contar submissions (RPC de trigger no existe).
- **Fix:** try/catch con `console.warn` — el submit funciona aunque el contador no exista.

**Bonus — migración 057:** rol admin (id=1) sin permiso `categories` → `get_platform_stats` fallaba; se agregó `"categories":["create","read","update","delete"]` idempotente.

```
S14 cart 42703 ──► S15 checkout EMPTY_CART ──► S19 facturas ecommerce ausentes
```

**Lección:** al evaluar fallos en suites secuenciales, siempre priorizar el primer test del flujo; los siguientes suelen ser cascadas.

## 7. Hallazgos de arquitectura (sin fix, para considerar)

Estos no rompen los flujos probados pero son riesgos/deudas técnicas identificadas:

1. **`products`, `categories`, `inventory`, `offers`, `product_variants` no tienen `company_id`.** El aislamiento multi-tenant de catálogo/inventario no está garantizado por columna — depende de RLS/contexto. Verificar policies; considerar agregar `company_id` (P0 seguridad).
2. **Dos secretos JWT** (app vs PGRST): los JWT de negocio NO deben usarse contra PostgREST; solo service key.
3. **`node --watch`/nodemon** reinicia servicios silenciosamente → 503 transitorios en pruebas. El suite ahora tiene retry (3 intentos).
4. **Sin WebSocket** — el dashboard en vivo depende de polling (revisar `notifications-redesign`).
5. **`invoice_items`**: la facturación funciona, pero verificar si existe tabla de items de factura o si se deriva de `sale_items`.
6. **Pasarela de pago**: `payment-service` (3019) está en el gateway; el checkout con tarjeta cae a `pending` si no responde (fallback tolerante).
7. **`get_current_user_role()`** mapea `service_role`/`platform_admin` → `platform_admin` (necesario para el dashboard platform).
8. **Notificación de stock bajo** depende de `inventory.stock_low` — ahora funciona tras el fix de stock.
